### 3.1 Проверь, что iOS собирается

```bash
cd ~/Desktop/PROJECTS/PLINK/ios-2

  -destination 'generic/platform=iOS Simulator' \
```

Если ошибки вида `unable to write file ... No such file or directory` в `GoogleUtilities`/`nanopb` — это **не код**, а битая DerivedData:

```bash
rm -rf ~/Library/Developer/Xcode/DerivedData/Plink-*
```

### 3.2 Прогони тесты

```bash
xcodebuild test -project Plink.xcodeproj -scheme Plink \
  -destination 'platform=iOS Simulator,name=iPhone 16'
```

### 3.3 Бэкенд: **есть непринятая миграция**

```bash
cd ~/Desktop/PROJECTS/PLINK/backend-3
npm install
npx prisma migrate deploy     # миграция 20260726120000_moderation_gdpr_indexes
npx prisma generate           # ОБЯЗАТЕЛЬНО: в схеме новые поля
npm run build
npm test
```

**Порядок важен:** сначала миграция, потом код. Новый код обращается к полям, которых до неё нет.

> ⚠️ Проверка покупок теперь **fail-closed**: без переменной `APPLE_ROOT_CA_PEM` она отключается. Это осознанно — «проверять как получится» хуже, чем не проверять. Задай сертификат Apple Root CA (G3) в переменных Railway, иначе покупки не подтверждаются.

При старте в логах должно быть `[iap] самопроверка проверки покупок пройдена`. Если `САМОПРОВЕРКА ПРОВАЛЕНА` — проверка снова пропускает подделки, разбирайся немедленно.

## 4. Ловушки проекта — прочитай, сэкономишь часы

1. **Новые `.swift` файлы не попадают в сборку.** В репозитории лежит и `project.yml` (XcodeGen), и сгенерированный `Plink.xcodeproj/project.pbxproj`, где файлы перечислены **явно**. Если создаёшь новый файл — либо прогони `xcodegen generate`, либо добавь код в существующий файл. Иначе «код есть, а его нет».

2. **Ошибки компиляции идут волнами.** Swift останавливает проверку типов пофайлово. Исправил один файл — вылезет следующий. Это нормально, не паникуй.

3. **`.allowBluetoothHFP` — правильно для этого проекта.** В `project.yml` заявлен `xcodeVersion: 16.0`, но реальный SDK — iOS 26.5, где это корректное имя. Не меняй на `.allowBluetooth`.

4. **Бэкенд — ESM.** Импорты с расширением `.js`, `require()` недоступен. Используй статические импорты.

5. **Три UI-слоя одновременно:** `Plink/V4/*`, `Plink/V5/*` и легаси `RaveClone*`. Отсюда двойная навигация и половина багов. Целевой — V5/Cinema2026.

6. **Мега-файлы:** `WatchRoomModel.swift` (75 КБ), `V4FriendsView.swift` (89 КБ), `DMChatView.swift` (84 КБ), `DMChatService.swift` (46 КБ). Читай целиком перед правкой — там легко не заметить контекст.

7. **Ассеты эмодзи — папка-ссылка, а не asset catalog.** Грузятся через `Bundle.main.url(forResource:withExtension:subdirectory:)`. Скачанные из сети картинки часто оказываются WebP с расширением `.png` — Xcode на них падает в pngcrush. Проверяй `file *.png`.

## 5. Что доделать — по приоритету

### P0 — без этого нельзя запускаться

**5.1 Решить судьбу голосового чата.**
`LIVEKIT_SFU=false` в проде, `/api/rtc/token` отдаёт 503. Либо задай ключи LiveKit, либо **честно спрячь микрофон в UI**. Показывать неработающую кнопку — худший вариант: у Hearo именно на голосе больше всего жалоб. Файлы: `Plink/RTC/RoomRTCController.swift`, `Plink/Services/PlinkPermissions.swift`, флаг в `FeatureFlags`.

**5.2 Замерить синхронизацию на трёх устройствах.**
Это главное конкурентное преимущество, и его нельзя заявлять без замера. В комнате есть значок «в синхроне · N мс». Прогони на трёх реальных устройствах, зафиксируй медиану и p95. Инструкция: `ios-2/MULTI_DEVICE_TEST_PLAN.md`.

**5.3 Экран пустой комнаты.**
Самая слабая точка воронки: создал комнату — ты один, и непонятно что делать. Нужен один экран: крупная кнопка «Позвать друга» (deep link и QR уже реализованы в `Plink/Features/WatchRoom/RoomInviteSheet.swift`), список друзей онлайн в один тап, подсказка «можно начать одному». Сейчас приглашение спрятано за иконкой в верхней панели.

**5.4 Довести Android до паритета по синхронизации.**
`ios-2/android-client/` — тонкий клиент, `sync.command` не применяется к плееру. Пока это так, **нельзя заявлять «кроссплатформенная синхронизация»**.

### P1 — качество продукта

**5.5 Убрать пустые кнопки.** В `WatchRoomModel.swift` пустые тела: `startPiP()`, `openPlayerSettings()`, `toggleCamera()`, `openInRutubeExternal()`. Либо реализуй, либо убери точки входа из UI. Пользователь нажимает — ничего не происходит.

**5.6 Дошифровать 2FA-секреты.** `twofaSecret` и `twofaBackupCodes` лежат в БД открытым текстом. Нужен ключ в окружении и разовая перешифровка существующих строк — это операция с данными, делай через скрипт с бэкапом.

**5.7 Подключить zod-валидацию.** `backend-3/src/middleware/validate.ts` написан, но **не импортируется ни одним маршрутом**. Навесь хотя бы на `auth`, `billing`, `rooms`, `messages`.

**5.8 Убрать хардкод админ-кода.** `ADM873IN7` в `backend-3/src/routes/auth.ts` — статичный, общий для всех админов, в исходниках, сравнивается не за постоянное время. Рабочий TOTP уже есть в `security.ts`.

**5.9 Вызвать `invalidateUserSnapshot`** в админских действиях бана и смены роли (`backend-3/src/routes/admin.ts`). Функция экспортирована из `middleware/auth.ts`. Сейчас бан из админки применяется в течение 30 секунд, а мог бы мгновенно.

**5.10 Мигрировать 42 обращения к старому ключу Keychain.** `KeychainHelper.read(for: "rave_auth_token")` в 26 файлах. Сейчас работает через дублирование ключа, но правильно — перевести всех на `AuthTokenStore.shared.token`. Чисто механическая замена, но проверь каждый файл сборкой.

**5.11 Свободный тариф должен иметь лимиты.** Сейчас они не enforced на сервере, поэтому и продавать премиум нечем. Предложение: бесплатно — YouTube/VK/Rutube, чат, реакции, до N участников; Plink+ — живые темы, эмодзи-паки, приоритетный голос, ИИ без лимитов, повышенные лимиты.

### P2 — долг и полировка

**5.12 Схлопнуть три UI-слоя до одного** (целевой V5/Cinema2026). Это источник навигационной путаницы.
**5.13 Разбить мега-файлы** на компоненты.
**5.14 Прогнать Instruments** по force-unwrap (~200+ `!` в проекте) — потенциальные краши.
**5.15 Единый язык интерфейса.** Часть подписей осталась на английском в русскоязычных экранах; строки надо завести в `LocalizationManager`, а не хардкодить.

## 8. Как работать и отчитываться

- **Проверяй запуском.** У тебя есть Xcode и терминал — это твоё преимущество перед предыдущим аудитом, который вынужденно работал статическим анализом.
- **Не правь вслепую платёжный путь и авторизацию.** Сначала тест, потом правка.
- **Перед удалением кода проверь использование** по всему проекту. В этом проекте уже находили мёртвые структуры, отличающиеся от живых одним словом в имени.
- **Правки в модерации и миграция БД пока проверены только компилятором** — прогони их на живой базе в первую очередь.
- Веди краткий журнал: что проверил, что исправил, что не смог и почему.
- Если находишь расхождение с отчётами выше — доверяй коду и запуску, а не отчёту, и явно отметь расхождение.
